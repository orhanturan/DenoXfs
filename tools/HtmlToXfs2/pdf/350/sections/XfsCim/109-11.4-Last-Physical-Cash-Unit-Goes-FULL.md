12. Appendix E – Cash Acceptor E2E Authentication
This section describes how to perform End to End authentication for Cash In transactions using the
WFS_CMD_API_START_SECURE_OPERATION and WFS_INF_API_SECURE_QUERY API calls. For a full
description of these command see section 13 of [Ref. 1].
An application can determine what functionality must be protected using E2E Authentication by calling the
WFS_INF_API_SERVICE_INFO command and referencing the lpE2EAuthentication parameter. This points to a
structure containing fields which detail the commands and queries that require authentication. If no authentication is
required, then lpE2EAuthentication is NULL.
Specified below is a description of the data that can be sent as part of a CIM cash-in transaction, and this is
followed by flow diagrams showing how various use cases can be executed.
Note: The entire sequence of accepting cash and ending a cash in transaction must be complete before retrieving the
token to send to the host. Any attempt to call WFS_INF_API_SECURE_QUERY to retrieve the token before notes
have been removed after a WFS_CMD_CIM_ROLLBACK, or before a WFS_CMD_CIM_RETRACT command
has completed will return a generic WFS_ERR_SEQUENCE_ERROR error code.
