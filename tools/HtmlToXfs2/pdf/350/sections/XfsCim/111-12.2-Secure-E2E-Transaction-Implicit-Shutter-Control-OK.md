12.2 Secure E2E Transaction (Implicit Shutter Control) - OK
The following flow describes a good E2E cash-in transaction flow where the shutter is implicitly controlled by the
Service Provider. All notes are good and accepted, the transaction ends with a credit to the customer account.
The WFS_CMD_API_START_SECURE_OPERATION should ensure that the internal areas of the module are
clear of any notes and that it is ready to begin a cash-in transaction.
The standard CIM commands are then used to accept cash into the device, then the
WFS_INF_API_SECURE_QUERY is used to 'wrap' the WFS_INF_CIM_CASH_IN_STATUS query. This query
retrieves the result as well as the token, including the HMAC to send to the host.

12.3 Secure E2E Transaction - Customer Returns Notes Using Rollback (Implicit
Shutter Control)
The following flow describes a good E2E cash-in transaction flow where the shutter is implicitly controlled by the
Service Provider. In this use case the customer enters notes but decides to cancel the transaction and return what
was entered. This is done using the WFS_CMD_CIM_ROLLBACK command.
The application issues the WFS_CMD_CIM_ROLLBACK command, and the customer then removes the bills.
Finally, the WFS_INF_API_SECURE_QUERY is used to retrieve the result as well as the token, including the
HMAC to send to the host to verify that nothing was accepted, and the customer account does not need to be
updated.

12.4 Secure E2E Transaction - Customer Returns Notes Using Rollback But Does
Not Remove The Notes (Implicit Shutter Control)
The following flow describes an E2E cash-in transaction flow where the shutter is implicitly controlled by the
Service Provider. In this use case the customer enters notes but decides to cancel the transaction and return what
was entered. The application issues the WFS_CMD_CIM_ROLLBACK command and the notes are returned, but
the customer does not remove them from the exit slot. The application then retracts the notes back into the device
using the WFS_CMD_CIM_RETRACT command.
The WFS_INF_API_SECURE_QUERY is then used to retrieve the result as well as the token, including the
HMAC to send to the host. The token reports that notes were accepted into the device and returned, but then
subsequently retracted back in.
